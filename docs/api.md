# HTTP API

Ручки перечислены в [README](../README.md#api). Интерактивная документация OpenAPI: `/docs`.
Авторизации нет, сервис рассчитан на внутреннюю сеть (см. [deploy.md](deploy.md#сетевой-доступ)).

## Пример ответа

`GET /runs/{run_id}` (сокращён):

```json
{
  "run_id": "a42ca2a68473",
  "status": "completed",
  "already_running": false,
  "started_at": "2026-11-13T21:39:24+10:00",
  "finished_at": "2026-11-13T21:45:27+10:00",
  "timed_out": false,
  "error": null,
  "stats": {"found": 70, "skipped": 0, "quarantined": 0, "deferred": 58, "read": 12,
            "failed": 0, "new": 124, "updated": 0, "seconds": 266.0,
            "search_seconds": 265.9, "tail_seconds": 0.1,
            "fetch_busy_seconds": 23.1, "llm_busy_seconds": 447.2},
  "events": [
    {
      "id": "442b6e21be4ff1a9216bf9e4255bca423ef72c7f",
      "change": "new",
      "title": "Кот в сапогах",
      "category": "kids",
      "start_date": "2026-11-14",
      "end_date": null,
      "start_time": "12:00",
      "city": "Владивосток",
      "venue": "Приморская краевая филармония",
      "price": "от 300 ₽",
      "is_free": false,
      "description": "Детский спектакль «Кот в сапогах»…",
      "event_url": null,
      "is_cancelled": false,
      "source_urls": ["https://vladivostok.ticketland.ru/spectacle"]
    }
  ]
}
```

## Поля события

`category` — одно из `concert`, `festival`, `exhibition`, `theater`, `lecture`, `workshop`,
`meetup`, `conference`, `standup`, `tour`, `quiz`, `kids`, `film`, `other`.
`start_time` — `HH:MM` или `null`; `is_free` — `true`/`false`/`null` (неизвестно);
`event_url` — только `http(s)`, для карточек подставляется адрес страницы.

`venue` заполняется, только если площадка есть на странице. На афишах (`watch_urls`) адресов
обычно нет, поэтому у событий с афиш поле чаще пустое; его добирают карточки из поиска.

## Что попадает в `events`

Только события, которых ещё не отдавали (`change: "new"`), и существенно изменившиеся
(`change: "updated"`: появилась площадка или время начала, событие отменено). Ключ `id`
стабилен между прогонами. Новые идут первыми, затем по дате и времени.

## Счётчики `stats`

`found` — уникальных URL после фильтров, `skipped` — уже прочитанные, `quarantined` — в
карантине, `deferred` — не вошли в лимит `pages_per_run` (уйдут в следующий прогон),
`read` / `failed` — страницы, обработанные LLM / не прочитанные.

Замеры: `search_seconds` — время поиска, `tail_seconds` — сколько страницы дожимались после
поиска (чем меньше, тем лучше они перекрылись с поиском), `fetch_busy_seconds` /
`llm_busy_seconds` — суммарная работа всех потоков (делите на `workers`, чтобы оценить загрузку).

## Где хранятся результаты

Результаты последних `history_size` прогонов лежат в памяти процесса и пропадают при
перезапуске: `GET /runs/{id}` вернёт `404`. Состояние дедупликации (`state_path`) лежит на диске
и перезапуск переживает. Поэтому забирайте результат сразу после завершения прогона: события уже
помечены как отданные и в следующем прогоне не повторятся.

`GET /state` отдаёт файл состояния как есть. Он обновляется в конце прогона, поэтому во время
прогона ручка показывает состояние на конец предыдущего.

## Один процесс

Сервис запускается одним процессом (`serve` без `--workers`), потому что активный прогон хранится
в памяти. Второй процесс или CLI-прогон блокируется через `flock` на `lock_path`, и `POST /runs`
возвращает `409`.
